Coal — the AI that proves the chip works

Describe a chip in English. Coal writes the RTL, writes an independent reference model of the specification, and refuses to call it finished until a real toolchain agrees with both.

Every “AI writes Verilog” demo has the same hole: the model writes the design and the test, so the test agrees with the bug. It looks right and isn’t. Coal removes the model from the trust path.

How the trust works

The design and the expected behaviour come from two different processes. The model never writes the testbench.

spec → RTL (Nemotron) · spec → Python reference model · model → generated testbench

Then a gate that has veto power:

lint→ simulation→ synthesis (ABC)→ formal→ place & route (iCE40)→ timing

The chip, as the tool sees it

Run it

# hosted inference (optional — falls back to local Ollama)
$env:NEBIUS_API_KEY  = "..."
$env:COAL_BASE_URL    = "https://api.studio.nebius.com/v1"
$env:COAL_AGENT_MODEL = "nvidia/nemotron-3-super-120b-a12b"

cd Coal\lm_track\coal_chat

# build and verify a chip
py -3.15 -c "import chipflow; r = chipflow.build('demo', spec='an 8-bit counter'); print(chipflow.summary_text(r))"

# the terminal UI
coal_tui\coal-tui.exe

The toolchain runs inside WSL; Coal detects it and installs iverilog verilator yosys gtkwave nextpnr-ice40 if missing.

Honest limits

  • 44/50, not 50/50. The six failures are listed with exact reasons.
  • FPGA, not ASIC. Timing is real iCE40 place-and-route; ASIC mapping is future work.
  • It is not a chip designer. 3/4 on well-specified sequential logic, 2/10 on terse specs. The toolchain is the only reason to trust any of it.
  • No local GPU. The GPU work happens in Nebius inference.
